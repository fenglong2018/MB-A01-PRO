## 83. 用户 · Thursday, Aug 20, 2026, 2:57 PM (UTC+8)

JLINK,那power那边不是要把JLINK共享给UBUNTU，用哪个指令

## 助手

在 **管理员 PowerShell** 里用 **usbipd**，把 J-Link 挂给 WSL2 的 Ubuntu（WSL2 默认看不到 Windows 的 USB）。

**1. 看设备（记 BUSID，例如 `1-4`）**

```powershell
usbipd list
```

找 `J-Link` / `SEGGER` 那一行的 `BUSID`。

**2. 第一次绑定（只需一次，要管理员）**

```powershell
usbipd bind --busid 1-4
```

把 `1-4` 换成你的 BUSID。

**3. 挂到 Ubuntu（每次拔插或重启后可能要再挂）**

```powershell
usbipd attach --wsl --busid 1-4
```

指定发行版时：

```powershell
usbipd attach --wsl Ubuntu --busid 1-4
```

想一直跟着 WSL：

```powershell
usbipd attach --wsl --auto-attach --busid 1-4
```

**4. 在 Ubuntu 里确认**

```bash
lsusb
# 应能看到 SEGGER
make flash
```

没有 `usbipd` 时，先在 Windows 装 [usbipd-win](https://github.com/dorssel/usbipd-win/releases)，Ubuntu 里还要有 Linux 版 J-Link（`JLinkExe`）。

卸下来：

```powershell
usbipd detach --busid 1-4
```

注意：挂给 WSL 后，**Windows 上的 J-Flash / J-Link 不能同时占用**同一把枪。Cursor 若用 Windows 侧 Cortex-Debug，就不要 attach；只用 WSL 里 `make flash`，才 attach。

## 87. 用户 · Thursday, Aug 20, 2026, 3:20 PM (UTC+8)

gdb-multiarch是做什么用

## 助手

**gdb-multiarch** 是调试器 **GDB** 的一种安装包：同一个程序能调试多种 CPU，包括你这块板的 **ARM Cortex-M4**。

调试时大致是这样：

1. **J-Link** 通过 SWD 连上芯片  
2. **JLinkGDBServer** 在电脑上开一个 GDB 端口  
3. **gdb-multiarch** 读 `build/User.elf`（带行号、变量名），连上这个端口  
4. Cursor 的 **Cortex-Debug** 就是在后面调它：你下断点、看变量、单步，都是 GDB 在干  

Ubuntu 里交叉编译常用 `gcc-arm-none-eabi`，但自带的 `arm-none-eabi-gdb` 经常没有单独打包，所以用仓库里的 **gdb-multiarch** 代替。它不是编译器，**不能**代替 `gcc-arm-none-eabi`；只负责「编出来的 elf 怎么跟芯片对上号」。

只烧录、不下断点，用 `make flash`（JLinkExe）就行，可以不装 gdb-multiarch。要在 Cursor 里 F5 单步，才需要它。

## 91. 用户 · Thursday, Aug 20, 2026, 3:44 PM (UTC+8)

怎么退出调试

## 助手

在 Cursor 里结束 J-Link 调试，用下面任一方式即可。

**最常用**
- 点调试工具栏上的红色方块 **Stop**
- 或按 **Shift+F5**

停掉后，GDB 和 J-Link GDB Server 会一起退出，芯片不再被调试器占用。

**注意**
- 只按 **Disconnect**（断开）有时会留下 `JLinkGDBServer` 进程；要用 **Stop**。
- 若工具栏没了、口还被占着，在 Windows 任务管理器结束 `JLinkGDBServerCL.exe` / `JLinkGDBServer.exe`；在 WSL 里可 `pkill JLinkGDBServer`。
- 想继续跑、只是暂时不看变量：用 **Continue（F5）**，不要 Stop。Stop 才是真正退出调试。

## 93. 用户 · Thursday, Aug 20, 2026, 3:48 PM (UTC+8)

我要烧录代码用make flash吗

## 助手

**用 F5 调试时，不必再 `make flash`。** Cortex-Debug 会把 `build/User.elf` 下到芯片，等于已经烧过一遍。

两种用法分开：

| 目的 | 怎么做 |
|------|--------|
| 下断点、单步、看变量 | Cursor 选 **J-Link (Windows)** 或 **J-Link (WSL)** → **F5**（会先跑 `make all` 再下载） |
| 只烧录、不调试 | WSL 里 `make` 再 `make flash` |

**不要一边 F5 开着、一边 `make flash`。** J-Link 同时只能被一边占用，会抢口。

日常开发：改代码 → **Shift+F5 停掉上次** → 再 **F5**。  
只想让板子自己跑、上位机看 CDC：先退出调试，再 `make flash`。

`make flash` 走 Linux 的 `JLinkExe`。你若 Linux 包没装好、枪还在 Windows 上，这条会失败；那种情况用 **F5（Windows）** 烧即可。

## 103. 用户 · Thursday, Aug 20, 2026, 4:50 PM (UTC+8)

没有插USB,LED3是PB2，也是BOOT1，那样接有问题吗？BOOT1一定也要接地或上拉吗

## 助手

**PB2 兼作 BOOT1 上接 LED，可以，不是硬错误。** 真正必须电平确定的是 **BOOT0**，不是 BOOT1。

N32WB452 和 STM32F1 一类，复位时采样启动脚：

| BOOT0 | BOOT1 (PB2) | 从哪里启动 |
|-------|-------------|------------|
| **0** | 任意 | **用户 Flash**（正常量产） |
| 1 | 0 | 系统存储（ISP） |
| 1 | 1 | SRAM |

所以：**BOOT0=0 时，BOOT1 不参与选启动源**，PB2 可以当 GPIO 推 LED。

**BOOT0**  
一定要有确定电平。跑 Flash 就 **下拉到地**（常见 10k）。不要浮空，也不要和 LED 抢这根脚。表里 BOOT0 也叫 LED3 的那颗，不要当软件灯用。

**BOOT1 / PB2**  
- 不必像 BOOT0 那样强制接地。  
- 量产 BOOT0 已下拉时，BOOT1 **可以不单独再拉**。  
- 建议：LED 若是低亮（阳极经电阻接 3.3V，阴极接 PB2），PB2 加 **弱上拉（如 10k 到 3.3V）** 更好：复位后灯灭、脚为高；软件再推挽拉低点灯。  
- 不要把 LED 直接把 PB2 死拉到地（会常亮，BOOT0=1 时还会误进 ISP）。

**和「没插 USB、LED3 常亮」的关系**  
复位后、固件还没配 GPIO 时，PB2 默认浮空。低亮 LED 会从 3.3V 经灯灌进浮空脚，**可能一直微亮或常亮**。固件把 PB2 配成输出并写成高之后应灭。若软件已关仍常亮：量 PB2 是不是已经被灯/电阻拉在低电平；不要和 BOOT0 那颗灯搞混。

结论：BOOT0 必须接地（Flash 启动）；BOOT1 不是必须接地。LED 接 PB2 可行，低亮时最好给 PB2 弱上拉。
